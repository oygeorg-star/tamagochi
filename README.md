# Тамагочи-кликер

Консольная игра на Python, реализованная с использованием объектно-ориентированного программирования.

Игрок ухаживает за виртуальным питомцем, зарабатывает монеты, покупает еду и лекарства, следит за здоровьем, голодом, усталостью и энергией питомца.

## Запуск игры

Для запуска требуется Python 3.10 или новее. Дополнительные библиотеки для самой игры не требуются.

Из корневой папки проекта выполните:

```bash
python main.py
```

## Управление

После запуска игры доступны следующие команды:

- `1` — пойти на работу и заработать монеты;
- `2` — купить еду;
- `3` — купить лекарство;
- `4` — покормить питомца;
- `5` — вылечить питомца;
- `6` — поиграть с питомцем;
- `7` — дать питомцу отдохнуть;
- `0` — выйти из игры.

При покупке еды или лекарства необходимо выбрать номер товара из предложенного списка.

Заработанные монеты можно потратить на покупку еды и лекарств. Купленные предметы сохраняются в инвентаре.

## Правила игры

- У питомца есть показатели голода, усталости, здоровья и энергии.
- Работа приносит монеты, но влияет на состояние питомца.
- Кормление уменьшает голод.
- Лечение восстанавливает здоровье и расходует применение лекарства.
- Игра расходует энергию питомца.
- Отдых восстанавливает энергию и уменьшает усталость.
- При низком уровне здоровья питомец считается больным, поэтому отдых становится менее эффективным.
- Если здоровье питомца достигает нуля, игра завершается.

## Проверка кода

Для проверки синтаксиса Python выполните:

```bash

```

Для проверки стиля кода с помощью Ruff:

```bash

```

Для дополнительной проверки с помощью Flake8 (при установленном пакете):

```bash

```

Для запуска автоматических тестов используйте Pytest:

```bash

```

Тесты проверяют работу игровой логики, взаимодействие с питомцем, покупки, инвентарь и основной игровой цикл.

# Урок 1. Подготовка к работе

## Введение

Вам предстоит написать на Python легендарную игру «Тамагочи». Её можно написать по-разному, но ваше решение должно быть реализовано на принципах ООП.

Ваша задача — реализовать часть логики игры, написать необходимые классы и имплементировать методы.

## Описание проекта

Сразу стоит сказать, что у нас будет не совсем обычный Тамагочи, а модифицированный и немного осовремененный (Ubisoft бы позавидовала).

Главное отличие - IDLE механика, которая будет обеспечивать динамику игре.

Суть игры - мы создаем питомца (кто это будет и как будет его имя - это предстоит решать вам), следим за его здоровьем, кормим и укладываем спать.

Но для всех действий требуются деньги (как в жизни, надо же) и деньги будут зарабатываться соответствующим действием - кликом или работой (*тут нужно подумать*).

Таким образом получается полу-тамагочи полу-кликер.

## Правила игры

Давайте поговорим о правилах игры:

- У питомца есть несколько показателей: голод, усталость, здоровье и энергия.
- Питомец может заболеть, это влияет на его здоровье и усталость.
- При падении здоровья ниже 0 игра заканчивается.
- Каждое действие влечёт за собой изменение какого-либо состояния питомца. Например, если мы кормим питомца, то у него уменьшается голод, но может уменьшиться и энергия.

## Общая логика и компоненты игры

Сначала мы будем писать основную логику игры, никак не привязываясь к тому, где и как она будет работать (с красивой графикой, в окне или в консоли и т. д.). Игра будет разделена на несколько компонентов и сущностей:

- Питомец (тамагочи) — отвечает за логику, связанную с питомцем.
- Еда — содержит данные о конкретной еде и её стоимости, применяется для кормления питомца.
- Лекарство — содержит данные о лекарстве и его стоимости, применяется для лечения питомца.
- Кликер — логика игры, отвечающая за получение монеток, которые можно потратить на еду и лекарства.
- Сущность игры — содержит логику по запуску игры, следит за её состоянием и при наличии соответствующих условий завершает её.

Отдельно стоит обсудить взаимодействие этих компонентов. Игра при этом не знает, что происходит при выполнении того или иного действия, но может знать, какие параметры передаются и что ожидается на выходе функций. За саму реализацию уже отвечают конкретные компоненты, они управляют сущностями питомца и осуществляют менеджмент ресурсов (лекарство, еда, деньги).

## Классы, методы, функции, игровой цикл

Весь код проекта разбит на классы.

Для основных сущностей определены интерфейсы, которые вы должны будете реализовать в своей игре.

Давайте разберем основные сущности и интерфейсы:

1. `AbstractClicker` — интерфейс для кликера. Методы и свойства:
   - `def __init__(self, income_per_click: int) -> None:` — инициализация кликера.
   - `def click(self) -> None:` — выполнение клика для получения монет.
   - `income_per_click: int` — свойство для получения количества монет за один клик.

2. `AbstractGame` — интерфейс для сущности игры. Методы и свойства:
   - `def __init__(self, tamagochi: AbstractTamagochi, clicker: AbstractClicker, all_food: list[Food], all_medicine: list[Medicine]) -> None:` — инициализация игры с передачей питомца, кликера и доступных товаров.
   - `def click(self) -> int:` — выполнение клика, начисление монет и обновление состояния питомца.
   - `def buy_food(self, food: Food) -> None:` — покупка еды с проверкой достаточности средств.
   - `def buy_medicine(self, medicine: Medicine) -> None:` — покупка лекарства с проверкой достаточности средств.
   - `def feed_tamagochi(self, index: int) -> None:` — кормление питомца выбранной едой из инвентаря.
   - `def heal_tamagochi(self, index: int) -> None:` — лечение питомца выбранным лекарством из инвентаря.
   - `def rest_tamagochi(self) -> None:` — отдых питомца.
   - `def play_with_tamagochi(self) -> None:` — игра с питомцем.
   - `def is_alive(self) -> bool:` — проверка, жив ли питомец.
   - `def is_sick(self) -> bool:` — проверка, болеет ли питомец.
   - `def get_status(self) -> dict[str, Any]:` — получение текущих характеристик питомца и количества монет.
   - `food: list[Food]` — свойство для доступа к имеющейся еде.
   - `medicine: list[Medicine]` — свойство для доступа к имеющимся лекарствам.

3. `Food` — класс-модель для представления еды. Имеет следующие поля-атрибуты:
   - `name: str` — наименование еды.
   - `satiety: int` — количество единиц голода, которое утоляет еда.
   - `price: int` — стоимость еды.


4. `Medicine` — класс-модель для представления лекарства. Имеет следующие поля-атрибуты:
   - `name: str` — наименование лекарства.
   - `price: int` — стоимость лекарства.
   - `heal_hp: int` — количество восстанавливаемых единиц здоровья.
   - `number_of_uses: int` — максимальное количество использований лекарства.
   - `uses: int = 0` — текущее количество использований. Не может быть больше `number_of_uses`.

   Методы:
   - `def is_empty(self) -> bool:` — проверка, закончились ли доступные использования лекарства.


5. `AbstractTamagochi` — интерфейс для тамагочи. Методы и свойства:
   - `def feed(self, food: Food) -> None:` — кормление питомца выбранной едой.
   - `def play(self) -> None:` — игра с питомцем.
   - `def rest(self) -> None:` — отдых питомца.
   - `def heal(self, medicine: Medicine) -> None:` — лечение питомца выбранным лекарством.
   - `status: dict[str, int]` — свойство для получения всех показателей питомца.
   - `def is_alive(self) -> bool:` — проверка, жив ли питомец.
   - `def is_sick(self) -> bool:` — проверка, болеет ли питомец.
   - `def update(self) -> None:` — обновление состояния питомца. Вызывается после игрового действия.
